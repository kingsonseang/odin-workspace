# BUG-1051 — Tasks without due dates appear first in due-date sort

- **ID:** BUG-1051
- **Status:** Open
- **Reported:** 2026-10-15
- **Observed in:** Task sorting
- **Environment:** Tasklane demo, Chrome on macOS, 1440×900 viewport
- **Frequency:** Every time

## Expected behavior

The **Due date (soonest first)** sort should place dated tasks from earliest to latest. Tasks with no due date should appear after every dated task, as specified in the sort rules.

## Actual behavior

The two tasks with no due date appear at the top of the list. All tasks with due dates, including one that is already overdue, appear below them.

## Steps to reproduce

1. Reset the demo data.
2. Ensure search is empty and both filters are set to **All**.
3. Set **Sort by** to **Due date (soonest first)**.
4. Inspect the first rows in the list.

The first two visible tasks are:

- Confirm analytics event names
- Keyboard focus in task form

Neither task has a due date. Dated tasks follow.

## Impact

A user reviewing upcoming or overdue work sees unscheduled tasks first, which pushes the most time-sensitive work below the fold. This can lead to incorrect prioritization during planning.

## Additional context

- Sorting by title and priority looked correct in the same session.
- The task with the earliest recorded due date is not at the top when this sort is active.
- The behavior persists after a refresh and after changing filters.
