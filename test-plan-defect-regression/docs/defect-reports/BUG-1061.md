# BUG-1061 — Editing from the details panel can reverse a completion

- **ID:** BUG-1061
- **Status:** Open
- **Reported:** 2026-10-18
- **Observed in:** Task details panel and edit form
- **Environment:** Tasklane demo, Chrome on macOS, 1440×900 viewport
- **Frequency:** Every time when following the sequence below

## Expected behavior

After a task has been marked complete, editing an unrelated field should not change its completion status. The edit form should save the task’s current values, and the task should remain **Done**.

## Actual behavior

If the task is completed from the list while its details panel is open, then edited from that panel, saving the form returns the task to **In progress**. The completion is lost even when the user only changes the title or description.

## Steps to reproduce

1. Reset the demo data.
2. Open the task **Fix mobile navigation overlap** in the details panel.
3. With the panel still open, check the task’s checkbox in the list. The row now shows **Done**, while the panel still shows **In progress** (see BUG-1056).
4. Choose **Edit task** in the details panel.
5. Observe that the edit form’s **Status** field says **In progress**.
6. Change the title to `Fix mobile navigation overlap – header`.
7. Choose **Save changes**.

The task returns to **In progress**, and the board’s **Done** count decreases.

## Impact

A routine title edit silently reverses a completion. This loses progress state, changes reporting totals, and can cause completed work to be picked up again.

## Additional context

- Starting the edit from the task row instead of the details panel did not reproduce the reversal in my attempt.
- I am not sure whether this is the same underlying problem as BUG-1056 or a separate issue. The visible symptom is different because this one changes saved data.
- The behavior also occurred when only the description was changed.
