# BUG-1047 — Status and priority filters return too many tasks

- **ID:** BUG-1047
- **Status:** Open
- **Reported:** 2026-10-14
- **Observed in:** Task filters
- **Environment:** Tasklane demo, Chrome on macOS, 1440×900 viewport
- **Frequency:** Every time both filters are used

## Expected behavior

When a specific status and a specific priority are selected, only tasks that match both selected values should remain visible. The specification says the two filters combine with AND.

## Actual behavior

When **In progress** and **High** are selected together, the board shows four tasks. Only one of them is both in progress and high priority. The other three match only one of the two selections. The visible-result text agrees with the number of rows, so the list is not merely displaying an incorrect count.

## Steps to reproduce

1. Reset the demo data.
2. Set **Status** to **In progress**.
3. Set **Priority** to **High**.
4. Review every visible row.

Expected visible task:

- Update the QA checklist for release

Observed visible tasks:

- Fix mobile navigation overlap
- Confirm analytics event names
- Update the QA checklist for release
- Write release notes draft

## Impact

A user trying to isolate a small, high-priority slice of active work sees unrelated tasks. This makes triage and stand-up review slower and can create the impression that more work is in a given state than is actually true.

## Additional context

- Using either filter on its own appears to show only matching tasks.
- The behavior is stable across refreshes.
- Search was empty during the observations.
